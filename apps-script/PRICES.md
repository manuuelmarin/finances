# Prices and daily exports

Release 3.9.1 keeps API 3.3.0 and the business workbook schema. Fixed HTTPS Quefondos routes use a validated ISIN, no redirects or HTML execution. Reference name, published title and `Divisa` must agree on explicit class currency, including cached quotes. A coherent USD class can retain the provider's verified EUR quotation. `tPrecios` stores NAV once per published date; conflicting same-date NAV is preserved for review. Failed, stale or weekend queries never create a NAV dated today.

## Historical import

`previewPriceHistory` is read-only. `importPriceHistory` accepts at most twenty observations, requires owner confirmation of the export's provenance, and binds product/ISIN/class/currency, workbook hash, revision and immutable UUID. The app previews and confirms each chunk through its normal queue. Confirm its receipt and reread before the next chunk. Recovery replays the exact payload/UUID; a revised NAV requires a new reviewed request. A conflict rejects the entire chunk; equal existing NAV is a duplicate. Imports add original dates older than today, including dates preceding the newest stored price. For a rounded historical source, backfill only dates strictly before the latest verified live-provider NAV for that product; leave that exact date and later dates to the daily updater. This preserves the strict same-date conflict check. Imports never interpolate, change cash or units, or silently overwrite NAV.

## Derived `Histórico` sheet

Build 3.9.1 refreshes an extra visible `Histórico` sheet after verified quote or historical-import writes and during `comprobarPaso4` preparation. Row 1 shows fund names, row 2 holds the corresponding ISIN/product keys, and row 3 shows `Inicio conocido (o Fecha base)`: a retained first-held override when one is present, otherwise the model's `Fecha base` for a positive base holding or its first recorded purchase date. `Fecha base` and trade dates describe the model's recorded position history; they do not independently prove the original acquisition date. Subsequent rows contain one Madrid calendar date per day through today. The view reads exact `tPrecios` values and current held units; it leaves cells blank before a holding, after a sale, on dates without a published NAV, and on non-trading days. It does not forward-fill. A row-3 start date is retained by matching the column ISIN and is accepted only for a current product and a bounded non-future date. A tab named `Histórico` without the generated marker is preserved. The extra view does not add a business sheet or table to the model schema; `tPrecios` remains the sole NAV source.

Download the app's empty CSV template. Columns in order: `isin,referenceName,classCurrency,quoteCurrency,date,price,provider,sourceUrl,exportedAt`. Every observation carries class name, ISIN, effective ISO date, EUR NAV, class currency, source description and UTC export timestamp. Preserve export precision. Use quoted comma decimals or semicolon CSV; do not include thousands separators, formulas or HTML. Exported XLS/XLSX files must first be reviewed and saved as this normalized CSV. `sourceUrl` is optional documentary provenance; supported manager hosts are fixed, and the importer never fetches it. For another manager, leave it empty and identify the original export/document in `provider`. Verification is explicitly **owner-reviewed export**, not independent server certification.

## Optional owner routines

Nothing installs or activates automatically. Test and production use different bindings, states, leases and receipts. Prefer separate Apps Script projects. `activarActualizacionDiariaPreciosTest` requires the test environment. Prepared production equivalent: `activarActualizacionDiariaPreciosProduction`; use it only after an independently approved production setup. Switching `ENVIRONMENT` never activates production. Deactivators are `desactivarActualizacionDiariaPreciosTest` / `desactivarActualizacionDiariaPreciosProduction`. They unlink first and remove only their own triggers/state.

Activation binds owner, workbook, Apps Script project and the installed trigger UID. Private `_` handlers verify effective owner, environment, project and UID, including while the active user is empty. Public app/editor routines require the active owner. Reinstallation removes duplicates, migrates obsolete schedules and preserves state only for the same binding. Rebinding requires reactivation. Copying script properties into a different project does not rescue its trigger binding.

The hourly trigger checks Madrid hours 20, 21 and 22. Each hour can requery even after an earlier valid quote aged at most four days; it distinguishes a newly added publication from a valid unchanged quote with publication pending. At most three confirmed attempts per batch/day, twenty products per batch, bounded execution budgets and recoverable uncertain-write UUIDs apply. Product selection changes reopen the ledger. NAV dates remain provider dates, including weekends. Locks and a lease prevent overlap; deactivation/book changes are rechecked before mutation. No financial positions are written.

`read`/`diagnostics` expose `dailyPrices`: installed/missing trigger, current execution due in the window, last successful run age, run receipt status and publication status. A successful request is not proof of a new daily NAV. Stale/conflicting/failed NAV stays pending. Rescue: inspect diagnostics, retain pending receipts, verify owner/environment/book/project, then deactivate and explicitly reactivate only the intended environment. Do not edit a pending UUID or copy another workbook's receipts. No real properties, triggers, production activation or deployments were changed by local tests.
