# Prices and historical data accumulation

`refreshPrices` preserves its revision, workbook, UUID, and receipt contract. Each confirmed NAV is added to `tPrecios` exactly once with its **published effective date**, never the query date. A price conflict for the same date requires review. Failed queries preserve the last price and are recorded in prices and the audit log.

## Verified sources and limits (9 October 2026)

The [Quefondos factsheet](https://www.quefondos.com/es/fondos/ficha/index.html?isin=ES0112611001) publishes the name, ISIN, currency, and an «Última valoración» (Latest valuation) section with EUR NAV and date. The linked ISIN is a research example, not a code catalog. The [mobile factsheet](https://www.quefondos.com/m/es/fondos/ficha/index.html?isin=ES0112611001) may publish a different date: each response retains its own date, without selecting a different share class or approximating the name. The official mobile variant is queried if the classic one fails because of HTTP, network, or format errors, but never after an inconsistency in identity, share class, currency, date, or price.

The [Quefondos help page](https://www.quefondos.com/es/fondos/ficha/ayuda_ficha.html) describes a historical chart. In the actual HTML, `var fondo` contains monthly samples and the latest sample. The [official JavaScript](https://www.quefondos.com/opencms/export/system/modules/com.vdos.site.qf.templates/resources/js/infofiucaract-lib.js) uses `corrigeArray` to fill gaps and transforms values into EUR returns rebased to 100. Month-end cutoffs include non-business days and do not establish individual NAV effective dates. They are not imported as a daily series into `tPrecios`.

[VDOS](https://www.vdos.com/es/datos.html) offers NAV and historical series using asset managers' data. A generic public daily endpoint with identity/share class/currency per row has not been verified. [Vanguard](https://www.vanguard.co.uk/professional/product/fund/bond/9132/20-year-euro-treasury-index-fund-euro-shares) does publish historical NAV tables and downloads for specific share classes; this does not demonstrate uniform access by ISIN across all asset managers. Completing history from before installation requires an exportable historical source verified by share class and currency, plus an additional adapter. The app must show this gap; it must not apply the current NAV retrospectively or interpolate.

## Optional daily updates for the test workbook

When updating `Code.gs`, also copy the current `appsscript.json` manifest. It includes the minimum permission `https://www.googleapis.com/auth/script.scriptapp`, required to [create, inspect, and delete triggers](https://developers.google.com/apps-script/reference/script/script-app). Google will require reauthorization of the project with that permission when installing from the editor; accepting the permission does not itself install the routine.

The **owner runs these functions from the Apps Script editor**:

- `activarActualizacionDiariaPreciosTest`: installs a single hourly trigger that queries only between 20:00 and 22:00 Madrid time; Google determines the execution minute, and the routine is explicitly bound to the test workbook ID.
- `desactivarActualizacionDiariaPreciosTest`: removes only this routine's triggers, disabling the binding first and deleting daily state. Reinstallation removes duplicates and migrates the old daily trigger; reactivating an existing installation preserves its receipts and attempts.
- `actualizacionDiariaPreciosTest`: accumulates real NAV using `refreshPrices`, batches of up to twenty products, and stable receipt UUIDs by date, workbook, selection, and attempt. A lost response recovers the receipt without consuming another attempt; a partial result allows up to three attempts per batch per day during hourly executions within the window. A day completes only with valid NAV no more than four calendar days old, updated or equal to the stored value. An old NAV, conflict, or failure leaves the day pending. Completed batches are skipped, and changes to products or ISIN bindings reopen the selection. A temporary lock prevents simultaneous executions; state is replaced daily in a single property. The routine stops when switching to production or changing the workbook ID.

Publishing this code does not install the trigger. Public functions verify the active user using the existing authorization. The private handler `actualizacionDiariaPreciosTest_` verifies the effective owner, test environment, activated workbook, and installed trigger UID before writing; its suffix prevents invocation from `google.script.run`. [Installable triggers](https://developers.google.com/apps-script/guides/triggers/installable) run under their creator's account.

Queries start new funds for a maximum of two minutes per batch, and the routine starts new batches for three minutes. A network request already started depends on Google's timeout. Once the time budget is reached, pending funds receive `TIME_BUDGET` and preserve their price. Money and units are not changed; cutoff dates follow the existing monotonic rule when saving NAV.

## Diagnostics

`responseInfo` includes HTTP status, official URL, presence of identity and labels, a bounded title, and response hash, together with attempts. It does not expose the source body or private network exception messages. Failures distinguish `SOURCE_HTTP_ERROR`, `SOURCE_RATE_LIMITED`, `NETWORK_ERROR`, format, identity, and date. `historyAvailability.status = LATEST_ONLY` declares the query's actual scope.

Local validation covers prices, identity and share class, conflicts, repeated UUIDs, partial failures, migrations, monthly gaps, and trigger lifecycle/retries with simulated services. No triggers were installed and no Google workbooks were written during this implementation.

`diagnostics` and `read` include `dailyPrices` without changing API 3.3.0: `enabled`, `status`, `schedule` (`timezone`, `hours`, `maxAttemptsPerBatch`), and `lastRun` (`today`, `checkedAt`, `complete`, `remaining`, `counts`, `status`). It distinguishes disabled, scheduled, missing trigger, inspection unavailable, complete, partial, retry limit, no products, and failure. Diagnostics do not activate anything, expose the workbook ID, or replace per-fund prices. `prices[].lastValid` adds `ageDays` and `freshness` (`current`, `delayed`, `invalid`) calculated using the Madrid date; a stored future price is marked invalid.

The chosen daily strategy is one general source, **VDOS / Quefondos**, with its two official variants by ISIN. The share class currency is preserved, and only the published EUR NAV is stored; for classes in another currency, conversion belongs to the provider. No subscription or licensed feed has been installed. This change adds neither asset-manager-specific adapters nor retrospective history. After copying and authorizing the code, the owner must run `comprobarPaso4`, `probarFuentesPaso4`, and `activarActualizacionDiariaPreciosTest` from the editor; the last function installs the trigger, while the preceding functions check preparation and the source. The result and **Ajustes** (Settings) allow activation and the latest attempt to be reviewed.
