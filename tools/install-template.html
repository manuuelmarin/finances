PASO 5 · ENTREGA {{BUILD_VERSION}} · API 3.3.0

        
Leer el libro y registrar operaciones

        
    
          
  1. 
            Sustituye los tres archivos del proyecto existente por estos bloques
            y guarda. Conserva TEST_SPREADSHEET_ID, OWNER_EMAIL y
            ENVIRONMENT=test. No cambies a la copia principal.
          
    2. 
          
  2. 
            Ejecuta comprobarPaso4 si necesitas preparar las
            hojas técnicas; después comprobarPaso5. Debe
            indicar API 3.3.0, doce tablas, backendReady y calculationReady
            correctos; buildVersion {{BUILD_VERSION}} y bridgeReady true.
            summaryReady comprueba que el resumen nativo dispone de cifras y
            precios al corte; no acredita la consulta de fuentes.
          
    3. 
          
  3. 
            Ejecuta probarFuentesPaso4. Esta prueba solo
            consulta. Revisa complete y cada
            results[].ok: ok:true en la respuesta general solo
            confirma que la función terminó. Un fallo incluye el estado HTTP,
            tamaño, título y huella de la página pública recibida, sin datos de
            tu libro. Conserva el último precio guardado.
          
    4. 
          
  4. 
            Actualiza la implementación: Implementar → Gestionar
            implementaciones → lápiz → Nueva versión. Mantén Ejecutar como: Yo y
            acceso Solo yo. El repositorio no actualiza automáticamente tu
            proyecto de Google.
          
    5. 
          
  5. 
            Vuelve a Finanzas y pulsa Abrir mi libro. Usa la
            cuenta propietaria. Mantén abierta la ventana de Google mientras
            usas la app. Debe aparecer Datos cargados con el resumen, cuentas y
            registros. Comprueba resumen, cortes y registros; después registra
            una operación de prueba y su anulación desde la revisión previa.
          
    6. 
          
  6. 
            Para consultar y guardar cotizaciones verificadas utiliza
            Inversiones → Actualizar precios o
            actualizarPreciosPaso4 desde el editor. No se
            sustituye un precio distinto de la misma fecha sin revisión. Un
            fallo no pone el fondo a cero.
          
    7. 
          
  7. 
            La app se puede instalar desde el navegador cuando lo permita. Los
            cambios pendientes quedan en este dispositivo; abre la app y Google
            para enviarlos. Una respuesta perdida conserva la solicitud y
            consulta su estado antes de reintentar. No se promete envío con la
            app cerrada.
          
    8. 
        

        

          El código mantiene pruebas si ENVIRONMENT=test. Los pasos siguientes
          preparan el uso real; la publicación del repositorio no cambia por sí

          Sheets; los filtros del listado no cambian los cortes financieros. Las
          copias locales permanecen en este navegador hasta borrarlas

COTIZACIONES · SOLO PRUEBAS

        
Acumular precios cada día

        

          Tras instalar esta entrega, ejecuta
          activarActualizacionDiariaPreciosTest desde el editor
          con la cuenta propietaria y concede el permiso para administrar esta
          rutina. La función instala un único trigger horario que consulta entre
          las 20 y las 22 h de Madrid, con hasta tres intentos por lote y día,
          vinculado al libro de pruebas. Publicar el código no activa la rutina.
        

        

          Ejecuta actualizacionDiariaPreciosTest para comprobar
          el primer lote. Revisa complete y cada resultado: una fuente fallida
          conserva el precio anterior. Para detenerla, ejecuta
          desactivarActualizacionDiariaPreciosTest. La rutina
          se detiene si cambias de libro o entorno.
        

        

          Se guardan valores liquidativos reales con la fecha publicada en
          tPrecios, sin duplicar producto y fecha. Los históricos verificados
          pueden importarse por fecha; si el archivo tiene menos precisión que
          la fuente diaria, importa solo fechas anteriores al último VL diario
          verificado de ese fondo y deja esa fecha y las posteriores al
          actualizador. La comprobación de conflictos de misma fecha permanece
          estricta. La vista Histórico deja en blanco los días sin VL publicado.
        

      

      

        
PASOS 6–8 · COMPROBACIÓN EN PRUEBAS

        
Terminar las pruebas y conservar el entorno

        
    
          
  1. 
            En test, ejecuta comprobarCierre o usa
            Ajustes → Diagnóstico del sistema → Comprobar sistema. Solo lee y consulta fuentes; no guarda precios. Comprueba
            buildVersion {{BUILD_VERSION}}, technicalReady true y todos los
            checks true. Un resumen correcto no acredita por sí solo las
            fuentes.
          
    2. 
          
  2. 
            En tu teléfono, instala desde el menú del navegador cuando lo
            permita. Abre la app sin conexión y vuelve a abrir Google para
            enviar los pendientes. Prueba una operación ficticia y su anulación
            únicamente en test, con restauración confirmada. Resuelve todos los
            pendientes de cada dispositivo antes del cambio.
          
    3. 
          
  3. 
            La activación del principal está suspendida hasta autorización
            expresa de Manu. El procedimiento siguiente se conserva como
            referencia futura; no lo ejecutes durante estas pruebas. Comprueba
            dónde están las últimas operaciones. Conserva una copia completa del
            libro principal y el XLSX original. Si alguno cambió después de la
            comparación, integra esas diferencias antes de declarar Sheets como
            única fuente. Conserva también el código y la configuración privada
            del proyecto.
          
    4. 
          
  4. 
            Para uso real, conserva el proyecto de pruebas y su enlace. Crea un
            proyecto y una implementación privados separados para el principal,
            usando estos mismos tres archivos. Configura OWNER_EMAIL,
            TEST_SPREADSHEET_ID con el libro de pruebas y
            PRODUCTION_SPREADSHEET_ID con el principal: deben
            ser distintos. Configura ENVIRONMENT=production.
            Ejecuta comprobarPaso4 para preparar el backend del principal y
            luego comprobarCierre. No ejecutes transacciones ficticias en
            producción: el código las rechaza.
          
    5. 
          
  5. 
            Publica Nueva versión como Yo y Solo yo, y guarda el nuevo /exec en
            la app. Debe mostrar Libro principal y pasar
            Comprobar sistema. No vuelvas a registrar como nuevas las
            operaciones ya migradas. Usa Sheets y esta API para las operaciones
            reales; conserva el XLSX como archivo histórico.
          
    6. 
        

        
Mantenimiento y recuperación

        

          Haz una copia nativa completa antes de cambios de código, fórmulas o
          importaciones y conserva copias periódicas con fecha, revisión y
          cortes. Guarda de forma privada OWNER_EMAIL, los identificadores y la
          configuración de la implementación: una copia de Sheets no respalda el
          proyecto de Apps Script.
        

        

          Para recuperar, detén los envíos y conserva el libro actual,
          pendientes y journal. Restaura la copia en otro libro, comprueba
          entradas, fórmulas y resumen, y recupera las operaciones posteriores
          usando auditoría, solicitudes y recibos. Nunca reenvíes en bloque
          pendientes sin confirmar: consulta primero su implementación original.
          Reconfigura una nueva implementación privada y comprueba su lectura
          antes de reanudar.
